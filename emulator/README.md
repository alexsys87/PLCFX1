# PLCFX1 Emulator — эмулятор ПЛК для отладки на ПК (Visual Studio 2026, C)

Консольная программа для Windows, которая запускает **настоящий код прошивки**
(`src/plc_serial_protocol.c` и выбранный интерпретатор `src/plc_runtime_minimal.c`
или `src/plc_exp_*.c`) на ПК. Заменено только «железо» платы BluePill:

| На плате | В эмуляторе |
|---|---|
| USART1 + DMA (19200 8N1) | COM-порт — один конец виртуального нуль-модема (VSPD, com0com) |
| Flash 0x0800C000..0x0800FFFF | файл образа `plcfx1_flash.bin` (программа сохраняется между запусками) |
| ОЗУ ПЛК 0x20002000 | те же адреса, зарезервированные в процессе (`VirtualAlloc`) |
| Входы X0..X7 | клавиши `0`..`7` в консоли |
| Выходы Y0..Y7, светодиоды RUN/ERR | состояние в консоли (`i`) и в логе |
| TIM2, тик 1 мс | таймер ПК (`QueryPerformanceCounter`) |
| RTC (LSE) | часы ПК + смещение (TWR/M8015 меняют только смещение) |

**Все ошибки пишутся в лог-файл** (`plcfx1_emulator.log` по умолчанию, дописывается):
ошибки запуска, ошибки COM-порта (открытие, чтение/запись, framing/parity/overrun),
каждый NAK с расшифровкой причины и байтами запроса, сбои ПЛК (код, шаг программы,
слова инструкции), ошибки flash, M8063, слишком долгий скан (> D8000), незакрытая
критическая секция, а также аварийное завершение (access violation и т. п.).

## Сборка в Visual Studio 2026

1. Откройте `emulator/PLCFX1Emulator.sln`.
2. Выберите конфигурацию и платформу:
   - `Debug` / `Release` — минимальный профиль интерпретатора (по умолчанию в прошивке);
   - `DebugExperimental` / `ReleaseExperimental` — экспериментальный профиль FX1N;
   - платформа `x64` или `x86` (обе поддерживаются).
3. *Build → Build Solution*. Результат: `emulator/bin/<платформа>/<конфигурация>/PLCFX1Emulator.exe`.

Проект использует набор инструментов **v145** (VS 2026) и язык **C17**. Для более
старой Visual Studio: *Project → Retarget solution*. Нужен компонент
«Разработка классических приложений на C++».

По F5 эмулятор запускается с `--port COM5`. Поменять порт: *Project → Properties →
Debugging → Command Arguments*. Рабочий каталог — папка с exe, там же появятся лог и
образ flash.

## Подключение через виртуальный нуль-модем

1. В Virtual Serial Port Driver (или com0com) создайте пару, например **COM5 ⇄ COM6**.
2. Запустите эмулятор на одном конце:
   ```
   PLCFX1Emulator.exe --port COM5
   ```
3. Программу-клиент (ваш софт, GX Developer, `tools/plc_link.py`) подключите к **COM6**,
   19200 бод, 8N1, без управления потоком:
   ```
   python tools/plc_link.py --port COM6 identify
   python tools/plc_link.py --port COM6 smoke examples/always_on_m0.hex --seconds 3
   python tools/plc_link.py --port COM6 smoke examples/clock_y0.hex --seconds 3
   ```

Как и плата, эмулятор стартует в **STOP**. RUN — командой клиента (E7 0E24),
клавишей `r` или ключом `--run`.

## Параметры командной строки

| Ключ | Назначение |
|---|---|
| `--port COMn` | COM-порт эмулятора (обязателен). Без него выводится список портов |
| `--baud N` | скорость, по умолчанию 19200 |
| `--log FILE` | лог-файл, по умолчанию `plcfx1_emulator.log` |
| `--flash FILE` | образ flash, по умолчанию `plcfx1_flash.bin` |
| `--factory` | стереть сохранённую программу (только END) |
| `--run` | запросить RUN при старте |
| `--trace` | писать в лог каждый запрос и ответ (уровень TRACE) |
| `--flash-fail` | все записи/стирания flash завершаются ошибкой (проверка NAK) |
| `--scan-delay MS` | пауза между сканами, по умолчанию 1 мс (0 — без пауз, 100 % ядра) |
| `--quiet` | в консоль только предупреждения и ошибки |
| `--no-keys` | не читать клавиатуру (запуск из скриптов) |
| `--list` | показать COM-порты и выйти |

## Клавиши в консоли

`0`..`7` — переключить вход X0..X7 (с антидребезгом 10 мс, как на плате) ·
`r` RUN · `s` STOP · `c` сбросить ошибку ПЛК · `i` состояние · `p` начало программы ·
`t` трассировка обмена вкл/выкл · `f` имитация отказа flash вкл/выкл · `h` помощь ·
`q`/Esc/Ctrl+C — выход (лог и образ flash корректно закрываются).

## Формат лога

```
2026-10-14 06:49:44.637 [ERROR] [PROTO ] NAK for request [0 read RAM 0x0000, 1 byte(s)]: checksum mismatch: frame carries 00, sum of command..ETX is 54
2026-10-14 06:49:44.638 [ERROR] [PROTO ]   request bytes: <STX>0000001<ETX>00
2026-10-14 06:49:45.049 [ERROR] [PROTO ] NAK for request [1 write RAM 0x01C0, 1 byte(s)]: the write covers byte 0x01C0 (M8000..M8007), which is protected; use E7 0E24 / E7 0E25 for RUN/STOP
2026-10-14 06:49:45.656 [ERROR] [PLC   ] PLC FAULT 1 - OPCODE: instruction word is not supported by this runtime profile
2026-10-14 06:49:45.656 [ERROR] [PLC   ]   at step 0: words FFFF FFFF 000F (D8067=1, D8068=0, M8065=1); the PLC is in STOP
2026-10-14 06:51:03.088 [ERROR] [FLASH ] Flash write of block 0x0800C000 failed (fault injection is ON)
2026-10-14 06:51:33.489 [ERROR] [SERIAL] Cannot open COM9: Windows error 2 (File not found) - check the port name of the virtual null-modem pair
```

Уровни: `TRACE` (обмен, только с `--trace`/`t`), `DEBUG`, `INFO` (RUN/STOP, загрузка
программы), `WARN` (шум вне кадра, оборванный кадр, медленный скан), `ERROR`, `FATAL`.
Категории: `SYSTEM`, `SERIAL`, `PROTO`, `PLC`, `FLASH`, `IO`. В конце сессии
пишется сводка: число ошибок и предупреждений по категориям.

Причина NAK определяется эмулятором по тем же правилам, что в `Process_switch()`;
ответ всегда формирует сама прошивка, эмулятор его не меняет.

## Автоматическая проверка ошибочных сценариев

`tools/error_scenarios.py` отправляет 19 заведомо неверных запросов (неверная КС,
неизвестная команда, выход за границы, защищённый байт M8000..M8007, слишком длинный
кадр, шум, оборванный кадр, …), затем загружает программу с неподдерживаемой
инструкцией и проверяет, что RUN не проходит. В конце восстанавливается пустая программа.

```
python emulator/tools/error_scenarios.py --port COM6
```

Ожидаемый результат: `0 failure(s)`, а в логе эмулятора — по записи с причиной на каждый сценарий.

## Как устроен эмулятор

| Файл | Назначение |
|---|---|
| `host/platform.h` | замена `inc/platform.h`: типы, регистры USART1/DMA1 как переменные, PRIMASK. Подключается принудительно (`/FI`) |
| `src/emu_main.c` | аргументы, главный цикл (как в `App/main.c`), наблюдение за ошибками ПЛК, консоль, обработчики сбоев |
| `src/emu_serial.c` | COM-порт Win32, ошибки линии, автоматическое переоткрытие |
| `src/emu_protocol.c` | наблюдение за обменом: трассировка и расшифровка причин NAK |
| `src/emu_memory.c` | фиксированные адреса flash/SRAM, замена `plc_memory.c` и `plc_flash.c`, файл образа |
| `src/emu_io.c`, `src/emu_rtc.c`, `src/emu_board.c` | замены `plc_io.c`, `plc_rtc.c`, `board_clock.c` и ядра Cortex-M |
| `src/emu_log.c` | лог-файл |

Прерывания (байт USART, завершение DMA, тик 1 мс) доставляются между шагами главного
цикла, а не посреди кода прошивки. Это один из допустимых порядков выполнения для
настоящей прошивки, поэтому код протокола и интерпретатора работает без изменений.

## Ограничения

- Это не модель STM32: тайминги UART/DMA, время записи flash, пропадание питания,
  электрические параметры не моделируются. Байты, присланные клиентом до получения
  ответа на предыдущий запрос, эмулятор обработает, а плата может их отбросить.
- Совместимость с GX Developer/GX Works2 не проверялась (как и у самой прошивки).
- Программа хранится в образе flash в том же формате, что на плате (заголовок 0x5C байт +
  слова программы); сохранение/восстановление retained-данных при старте не выполняется,
  как и в текущей прошивке.
- Эмулятору нужны свободные адреса 0x08000000 и 0x20000000 в своём процессе. Если они
  заняты (редко, из-за сторонних DLL), в лог пишется FATAL с владельцем диапазона.
